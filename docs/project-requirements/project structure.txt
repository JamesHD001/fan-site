Current backend data model

The backend currently revolves around these 15 core MongoDB/Mongoose models:

User
 ├── memberships
 ├── bookings
 ├── gifts
 ├── payments
 ├── notifications
 └── posts/comments/interactions

Celebrity
 └── community content

Post
 ├── Comment
 └── Like

MembershipPlan
 └── Membership
      └── MembershipCard

MeetingType
 └── Booking

Gift
 └── GiftTransaction

Event

Payment

Notification
Models we've established
Model	Purpose
User	Registered platform users
Celebrity	Celebrity/fan-community profile
Post	Community posts
Comment	Post comments
Like	Post/content likes
MembershipPlan	Available membership tiers
Membership	User's purchased membership
MembershipCard	Digital membership card
MeetingType	Types of celebrity meetings
Booking	Meeting reservations
Gift	Available gifts
GiftTransaction	Gift purchase/transaction record
Event	Community events
Payment	Central payment transaction record
Notification	User notifications
💳 Payment architecture

This is one of the areas we've already actively implemented.

The payment flow is intended to be:

Frontend
   │
   ▼
Backend API
   │
   ▼
Payment Controller
   │
   ▼
Paystack Service
   │
   ├── Initialize Transaction
   │
   ▼
Paystack
   │
   ▼
Payment
   │
   ▼
Paystack Webhook
   │
   ▼
Payment Verification
   │
   ▼
Membership / Booking / Gift

We have already worked with:

services/paystackService.js
services/exchangeRateService.js
utils/currency.js
controllers/paymentController.js
models/Payment.js

And the Payment model supports transaction types such as:

MEMBERSHIP
MEETING
GIFT

We also successfully tested the real-time exchange-rate API, and it returned the current exchange rate successfully.

So the currency/payment architecture is not merely a mock/demo system.

🗂️ Root-level architecture

The most important distinction is:

celebrity-fan-site/
│
├── frontend/       ← React/Vite client
│
├── server/         ← Node/Express REST API
│
├── database/       ← Seeds + database scripts
│
├── docs/            ← Technical/project documentation
│
├── tests/           ← Automated testing
│
├── package.json
├── README.md
└── .gitignore

That is the structure I recommend we keep as the canonical project architecture rather than continually moving files around as new features are added.
